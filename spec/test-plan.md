# Contract test plan — named invariants and required test layers

Companion to `normative.md`. Each invariant has a stable ID; Foundry invariant/fuzz tests
MUST reference these IDs in their names (e.g. `invariant_I4_bondConservation`) so coverage
is auditable against this list. A new mechanism means new IDs here in the same commit.

## Layer 1 — vector conformance (exists)

Golden vectors from `vectors/` wired into forge tests: MMR roots, decomposition/merge,
inclusion proofs (§5–§7), z preimages (§8), custody indices (§9), and the circuit
public-value encodings (§14, `public_values.json`). FOUR independent consumers must
agree: Solidity, the Rust reference, the Python generator, and the circuit guest logic
(`circuits/common`, tested natively — the exact code the SP1 guests prove). The
barycentric evaluation additionally triangulates against c-kzg via the fixture tool. **When the contracts phase starts, add
an `eip712.json` vector file** (typehashes, domain separator for a fixed dummy chain
id/address, struct digests) generated by `scripts/gen_vectors.py` and consumed by both
the Rust crate and forge tests.

## Layer 2 — Foundry invariant suite

### ETH conservation and flow

- **I1 — solvency:** instance balance ≥ Σ stakes of ACTIVE/UNBONDING providers
  + Σ bonds of open challenges + Σ claimable ledger.
- **I2 — stake destination:** across any call sequence, stake ETH leaves the instance
  only as (a) full stake to the provider's withdrawal address on withdraw, or
  (b) bounty + paymaster split on slash. No other sink, ever.
- **I3 — single distribution:** each provider's stake is distributed at most once
  (withdraw XOR slash; a second distribution path must be unreachable).
- **I4 — bond conservation:** every challenge bond ends wholly in exactly one place:
  operator (answered) or challenger (timeout resolution or post-slash refund). Never
  split, never stranded outside the claimable ledger.
- **I5 — slash arithmetic:** distribution on slash = bounty (`stake·bountyBps/10000`)
  + paymaster remainder, summing exactly to `stake`.

### Provider state machine (§13.1)

- **I6 — monotonicity:** observed transitions ⊆ {NONE→ACTIVE, ACTIVE→UNBONDING,
  ACTIVE→SLASHED, UNBONDING→EXITED, UNBONDING→SLASHED}. EXITED and SLASHED are terminal.
- **I7 — exit liveness and bound:** withdraw is impossible before
  `unbondingAt + unbondingDelay`; with no open challenges it succeeds at that time; new
  challenges are unopenable at `now ≥ unbondingAt + unbondingDelay`, so exit is always
  reachable by `unbondingAt + unbondingDelay + responseWindow`.
- **I8 — counter integrity:** `openChallenges` equals the number of unresolved challenge
  records for that provider, across every interleaving.
- **I9 — challenge admission:** no challenge can open against EXITED, SLASHED, unknown,
  or late-UNBONDING providers (per I7 window).
- **I10 — exit pinning:** every challenge opened against an UNBONDING provider pins
  `(exitRoot, exitLeafCount)`; its indices are `< exitLeafCount`. No exiting provider is
  ever answerable for post-initiation data.

### Commitment state (§5–§6)

- **I11 — structure:** after every declaration, `len(peaks) == popcount(leafCount)` and
  `leafCount` increased by exactly the declared `m ≥ 1`.
- **I12 — differential root:** for random append sequences, the contract's stored peaks
  and computed `Root` equal the Rust reference implementation's (fuzz harness drives both
  with identical inputs; vectors cover fixed cases, this covers random ones).
- **I13 — intent replay:** each signed struct applies at most once; nonces per space are
  strictly sequential; a digest valid on one instance/chain reverts on another.

### Custody (§13.3)

- **I14 — commit discipline:** at most one commit per (provider, period); `submitProof*`
  succeeds only in its commit's period; an expired commit can never be used.
- **I15 — lapse safety:** `lapse()` succeeds iff status ACTIVE and
  `now ≥ anchor + (lastProven+3)·custodyPeriod + lapseGrace`. Never during grace, never
  on UNBONDING/SLASHED, and never after an accepted proof reset the clock (cure always
  wins if it lands first).
- **I16 — proof monotonicity:** `lastProven` never decreases; an accepted proof sets it
  to the current period.

### Paymaster (§15)

- **I17 — bucket bound:** bucket level ≤ cap at all times; total reimbursed over any time
  window `w` ≤ cap + rate·w.
- **I18 — ledger integrity:** `outstanding == Σ contributions`; reclaim payouts never
  exceed balance; if every donor reclaims during dormancy, final balance is ≤ dust
  (telescoping pro-rata, slash inflows swept).
- **I19 — authority:** `reimburse`/`absorbSlash` callable only by the instance; nothing
  else moves paymaster funds except reclaim and claim.
- **I20 — payout totality:** any failed push credits `claimable` for the exact amount;
  claimable balances are always eventually claimable (no state can freeze them).

## Layer 3 — negative tests

Every §16 error must be triggered by at least one test (selector-matched). Notably:
wrong-chunk challenge responses (the §7.2 "verifier that accepts everything" trap),
pin-preimage mismatches, out-of-range/duplicate indices, second `beginProof` in a period,
lapse during grace, withdraw with open challenges, reimbursement past the bucket.

## Layer 4 — fork and environment tests

- Point-evaluation precompile (0x0A) exercised on a mainnet-fork with a real KZG opening
  (c-kzg-generated fixture), not a mock.
- `blobhash()` paths driven with Foundry's blob cheatcodes (`vm.blobhashes`); the exact-
  blob-count check (`blobhash(B) == 0`) covered both ways.
- ERC-1271 flow tested against a real deployed Safe implementation on the fork, including
  the SafeMessage nesting, not a toy wallet mock.

## Layer 5 — process

- Mock SP1 verifier must implement the `(vkey, publicValues, proof)` interface per the
  §14 reservation note, so swapping in the real verifier changes no call sites.
- `/code-review` on every PR; a full multi-agent review (`/code-review ultra`) before
  merging each contract milestone; external audit before any mainnet deployment.
- Coverage gate in CI once contracts exist (`forge coverage`); mutation testing
  (e.g. gambit) is optional but recommended before audit.
